# System brief: Mifos X Web App

## Purpose

This is the browser interface for the Mifos X financial-inclusion platform, built on Apache Fineract; the repository describes it as the default web application for the Mifos community ([README.md](../README.md#L3-L11), [package.json](../package.json#L1-L10)). **Inference:** its principal users are financial-institution operations staff, because the application exposes client, loan, savings, accounting, collections, organization and reporting modules, including client creation and loan transaction workflows ([app.module.ts](../src/app/app.module.ts#L109-L129), [clients.service.ts](../src/app/clients/clients.service.ts#L61-L74), [loans.service.ts](../src/app/loans/loans.service.ts#L38-L45)). The business function is to give those users a working surface for customer records and financial operations rather than to run the financial ledger in this browser application ([clients.service.ts](../src/app/clients/clients.service.ts#L61-L74), [loans.service.ts](../src/app/loans/loans.service.ts#L77-L95), [Dockerfile](../Dockerfile#L39-L49)).

## Architecture

The code is a TypeScript/HTML/SCSS Angular single-page application with Angular Material, feature modules and shared HTTP interceptors for API URL prefixing, authentication, errors and optional caching ([README.md](../README.md#L3-L11), [package.json](../package.json#L37-L48), [app.module.ts](../src/app/app.module.ts#L109-L143), [core.module.ts](../src/app/core/core.module.ts#L71-L118)). Angular builds browser assets; the provided multi-stage container builds them with Node and serves them from Nginx on port 80, substituting runtime configuration into the browser-served environment script at startup ([angular.json](../angular.json#L19-L38), [Dockerfile](../Dockerfile#L1-L9), [Dockerfile](../Dockerfile#L35-L49), [index.html](../src/index.html#L30-L44)). The supplied Compose file runs the web container on host port 4200 and passes Fineract endpoint, tenant, language and session settings; this is a deployment recipe, not evidence of the production topology ([docker-compose.yml](../docker-compose.yml#L3-L26)).

## Data stores

This repository's container definition serves static files and does not provision an application database; **inference:** durable financial records live behind the separate Fineract API, whose backend the setup guide says must be supplied independently ([Dockerfile](../Dockerfile#L39-L49), [docker-compose.yml](../docker-compose.yml#L3-L27), [README.md](../README.md#L21-L30), [clients.service.ts](../src/app/clients/clients.service.ts#L61-L74)). In the browser, session storage holds credentials by default; an enabled “remember me” flow can store credentials and OAuth tokens in local storage, while local storage also holds selected server and tenant settings ([authentication.service.ts](../src/app/core/authentication/authentication.service.ts#L56-L73), [authentication.service.ts](../src/app/core/authentication/authentication.service.ts#L93-L100), [authentication.service.ts](../src/app/core/authentication/authentication.service.ts#L391-L415), [settings.service.ts](../src/app/settings/settings.service.ts#L66-L95)). An optional GET-response cache starts in memory and can be configured to persist in browser session or local storage ([http-cache.service.ts](../src/app/core/http/http-cache.service.ts#L28-L40), [http-cache.service.ts](../src/app/core/http/http-cache.service.ts#L110-L131)).

## Integrations

Inbound use is through the browser; outbound Angular HTTP calls reach Fineract endpoints for clients, loans and reports, with a configurable API base URL and a tenant header ([index.html](../src/index.html#L52-L71), [clients.service.ts](../src/app/clients/clients.service.ts#L61-L74), [reports.service.ts](../src/app/reports/reports.service.ts#L28-L46), [api-prefix.interceptor.ts](../src/app/core/http/api-prefix.interceptor.ts#L23-L47), [authentication.interceptor.ts](../src/app/core/authentication/authentication.interceptor.ts#L20-L48)). Authentication can use Basic authorization or OAuth2/OIDC bearer tokens, with optional two-factor token handling; the OAuth modes use authorization-code flow and a configured identity provider ([oauth.config.ts](../src/app/core/authentication/oauth.config.ts#L12-L29), [oauth.config.ts](../src/app/core/authentication/oauth.config.ts#L52-L96), [authentication.service.ts](../src/app/core/authentication/authentication.service.ts#L179-L207), [authentication.interceptor.ts](../src/app/core/authentication/authentication.interceptor.ts#L51-L69)). The development-server proxy forwards Fineract requests to a configured sandbox; it is not the Nginx container's API proxy ([package.json](../package.json#L16-L20), [proxy.conf.js](../proxy.conf.js#L19-L29), [Dockerfile](../Dockerfile#L39-L49)).

## Top 3 operational risks

1. **High — Browser-persisted authentication material.** Credentials and access tokens can be written to local storage with “remember me”; **inference:** a compromised browser session could expose account access and sensitive financial data. **Mitigation:** prefer short sessions and hardened browser/XSS controls; review whether persistent tokens are necessary ([authentication.service.ts](../src/app/core/authentication/authentication.service.ts#L93-L100), [authentication.service.ts](../src/app/core/authentication/authentication.service.ts#L148-L161), [authentication.service.ts](../src/app/core/authentication/authentication.service.ts#L391-L415)).
2. **High — Fineract dependency.** The documented setup requires a separate backend and client/loan actions invoke its API; **inference:** backend downtime or API incompatibility stops frontline work even when the web page loads. **Mitigation:** monitor API health and errors and coordinate versioned releases with the backend ([README.md](../README.md#L21-L30), [clients.service.ts](../src/app/clients/clients.service.ts#L61-L74), [loans.service.ts](../src/app/loans/loans.service.ts#L77-L95)).
3. **Med — Client-selected server and tenant.** Server URL and tenant identifier are kept in browser local storage and used to build API requests and tenant headers; **inference:** stale or incorrect settings can direct operations to the wrong environment or tenant. **Mitigation:** restrict allowed endpoints and validate tenant authorization at the backend ([settings.service.ts](../src/app/settings/settings.service.ts#L66-L95), [settings.service.ts](../src/app/settings/settings.service.ts#L160-L185), [authentication.interceptor.ts](../src/app/core/authentication/authentication.interceptor.ts#L20-L48)).
